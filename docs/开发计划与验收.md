# PixelFlow 开发计划与验收

本计划与 `架构与开发规格.md`、`openapi.json`、`schema.sql` 共同组成开发基线。全部功能目前为待开发；下列检查框默认未通过。估算是排期参考，实际投入需后续如实记录。

## 1. 实施顺序和阶段出口

| 阶段 | 内容 | 前置 | 出口条件 | 参考投入 |
|---|---|---|---|---|
| P0 契约与骨架 | 冻结依赖版本、前后端工程、Compose、迁移、种子素材、CI 骨架 | 本文档 | 容器启动、Java readiness、前端空壳、模板种子可读 | 3—5 小时 |
| P1 身份与上传 | Cookie 身份、分类/模板接口、文件校验和预览 | P0 | 双浏览器隔离；1/2 图模板均可上传和读取 | 4—6 小时 |
| P2 异步核心 | 受理、持久队列、三阶段、失败模拟、历史/结果、启动收尾 | P1 | API 能独立演示成功与三个阶段失败 | 6—9 小时 |
| P3 前端闭环 | 列表/详情/历史、上传状态、提交及多任务轮询 | P0 契约；真实联调依赖 P1/P2 | 多任务、刷新、查询异常、离页与身份清理全部可观察 | 6—9 小时 |
| P4 验证与交付 | 关键测试、容器烟测、无障碍检查、README、来源与证据 | P1—P3 | CI 全通过，验收逐项记录，无虚报完成 | 4—6 小时 |

合计约 23—35 人时，不是承诺工期。若时间不足，先减少视觉细节和可选功能，不删多阶段执行、隔离、错误区分和必需测试。串行队列、匿名身份、固定模拟图片已经是本方案的范围控制。

## 2. 后续 Agent 责任边界

本节是未来派工建议，本次只交付文档。是否同时启动多个 Agent 由用户决定。

| 工作包 | 负责文件 | 必须交付 | 不得自行改变 |
|---|---|---|---|
| 工程与集成 | Compose、Dockerfile、CI、根 README、版本锁文件 | 可复现运行、命令、集成记录 | 数据卷持久化、隔离运行规则 |
| 后端基础 | backend 中 identity/catalog/asset/storage、迁移和种子 | 私有资源鉴权、双端校验依据、媒体响应 | OpenAPI 字段、文件归属模型 |
| 后端执行 | backend 中 task/execution 及对应测试 | 状态机、短事务、队列、历史、模拟失败 | 阶段顺序、只读查询、终态不回退 |
| 前端 | frontend 源码与单元/组件测试 | 三页面、多任务 Hook、上传生命周期 | 状态枚举、查询错误语义 |
| 验收 | 测试证据、README 完成度、独立缺陷记录 | 核对 R-01—R-14、容器烟测 | 不可把未验证项标通过 |

同一文件只能有一个当前负责人；工程 Agent 管理共享构建文件与依赖修改。后端基础和执行共享 DTO/异常定义时先约定所有权。API Mock 必须来自 OpenAPI，最终验收必须切换到真实 Java/MySQL，不能以 Mock 验证替代集成。

推荐任务顺序：P0 完成后前端用契约 Mock 开发界面，后端依次完成 P1/P2；接口就绪后进行真实联调；最后统一验收。不要把“任务受理”和“轮询逻辑”拆给无共享契约的 Agent。

每个 Agent 的输入：本目录全部文档、其负责的工作包、可修改路径和前置产物。输出：变更摘要、实际测试命令与结果、未解决问题、契约变更、后续依赖；有 Git 仓库时附 commit，否则列出文件。发现规格冲突先报告并给出修订方案，不能静默另建接口。

可直接使用的派工模板：

> 阅读 docs 中的架构、接口、数据库和验收文件，完成工作包【名称】，限定修改【目录】。按契约实现，遵守不得递归删除用户文件的约束。不得把开发目标宣称为已完成，不得引入真实 AI/支付或额外账号系统。优先完成该包的出口条件及关键测试；交付实际变更、验证结果、已知限制与需要其他工作包配合的事项。接口或共享结构必须改动时先记录原因和影响，同步契约。

## 3. 开发流程与集成门槛

1. 核对用户文件及当前仓库状态，读取目录内 AGENTS.md；不覆盖已有工作。
2. 工程阶段冻结版本和接口类型；OpenAPI 生成 TS 类型或执行等价契约校验，Java DTO 与枚举显式对照。
3. 按业务切片实现：先能用 HTTP 演示，再接页面；每个切片完成对应核心测试。
4. 数据模型变化使用新增版本迁移，已经应用的迁移不随意改写；开发测试使用独立数据库。
5. 实现错误分支后再做视觉精修，不把失败场景留到交付前。
6. 每次合入前执行该工作包检查；共享字段变更触发两端相关测试。完整 CI 通过后不无目的重复全量测试。
7. 集成 Agent 使用新的独立测试卷验证首次启动，再验证同一卷重启；测试结束保留卷，不执行删除卷/递归清理。
8. 更新 README 和验收记录，清楚区分“源码已实现”“运行已验证”“未验证”“已知限制”。

CI 必须在 push 和 pull_request 触发，至少两个 job：frontend 执行 `npm ci`、`npm run lint`、`npm run typecheck`、`npm run test -- --run`、`npm run build`；backend 执行 `./mvnw -B verify`，包含测试和打包。脚本名由 P0 固定；ESLint 使用独立 CLI，不假定 Next 提供 lint 子命令。前端构建不要求后端在线；后端 MySQL 集成测试使用隔离 MySQL 服务或 Testcontainers。

项目任务截图要求运行验收在容器环境进行。宿主只用于查看源码和调用容器工具；构建、依赖安装、测试和应用执行在容器/隔离 CI 环境。README 给出相应 Compose 命令和 Windows 可用的操作方式。

## 4. 后端关键测试

| 编号 | 场景与动作 | 必须断言 |
|---|---|---|
| B01 | 调用创建任务，阶段人为阻塞 | HTTP 已返回 202，DB 有任务及 3 步；阶段尚未完成；不能只断言响应“看起来很快” |
| B02 | 不发任何 GET，释放三个阶段屏障 | Worker 自己完成，顺序严格为检查→生成→整理，result 持久化 |
| B03 | 参数化 failAt 为三个阶段 | 之前步骤成功、命中步骤失败、之后 SKIPPED；无结果；失败原因落库 |
| B04 | 重复查询已完成任务 | 状态、revision、updatedAt 均不变化；查询不能调用执行器 |
| B05 | 连续受理 A/B/C | 各自 ID、素材和状态独立；串行队列按创建时间及 ID 领取 |
| B06 | 错数量、重复 ID、错模板、非法 MIME、超限/伪造文件 | 正确 4xx；不创建任务或不保存无效素材记录 |
| B07 | 用户 B 读取/提交用户 A 的素材、任务和结果 | 404；不泄露拥有者及私有内容；历史仅本人 |
| B08 | 阶段之间素材文件不可读、结果写入失败 | 捕获失败、正确阶段、后续不执行，无假成功 |
| B09 | 并发尝试领取同一 ID | 条件更新只有一个成功；阶段只执行一次（不代表外部提交幂等） |
| B10 | 受理或终态事务中注入 DB 失败 | 多表回滚，不留下成功任务缺结果；异常有 traceId |
| B11 | 预置 QUEUED/RUNNING/终态后启动 API | 前两者中断收尾、阶段一致；终态保留；就绪前收尾完成 |
| B12 | 历史分页过程中插入新任务 | 游标继续旧列表，无偏移导致的重复；非法游标 400 |
| B13 | 关闭模拟控制后带 simulation 请求 | 403；未带 simulation 的正常流程仍可完成 |

阶段顺序测试使用可注入时钟/等待器与同步屏障，不用数十秒 sleep 造成脆弱测试。至少一组 MySQL 集成测试验证真实事务、Mapper、JSON 类型映射、外键及检查约束，不能只用 H2 替代。

## 5. 前端关键测试

| 编号 | 场景 | 必须断言 |
|---|---|---|
| F01 | 模板要求分别为 1/2 张图 | 动态渲染准确；未全部 READY 禁止提交；校验可读 |
| F02 | 上传中替换/移除文件，旧响应晚到 | 不恢复旧 assetId；取消请求并释放旧 Object URL |
| F03 | 任务返回 202，后端仍运行 | 按钮结束提交态，任务卡出现，可再次明确创建任务 |
| F04 | A 成功、B 失败、C 运行交错响应 | 各任务状态、阶段、结果和错误不串扰 |
| F05 | 查询 HTTP 503/网络异常 | 保留最后 Task；显示查询异常；不标业务失败；点击恢复可继续 |
| F06 | 所有任务进入终态 | 后续定时器不再请求；新任务加入后恢复跟踪 |
| F07 | 离页或重新初始化身份时晚到响应 | 无旧页面/旧用户污染，abort 和 timer 清理生效 |
| F08 | 后来的快照 revision 小于本地 | 丢弃，终态不回退；列表刷新不会移除新提交任务 |
| F09 | 模拟浏览器刷新，服务器返回历史 | 恢复历史及非终态跟踪；终态不轮询 |
| F10 | POST 网络超时 | 提示受理未确认，不自动重发；提供历史确认入口 |
| F11 | 单任务 404、全局 401 | 404 仅停止该任务；401 停止全部并提示身份失效 |
| F12 | 任务成功但图片请求失败 | 显示预览错误，任务仍成功 |

用 fake timers + 可控延迟 Promise 测试轮询与竞态；计数请求和检查清理行为，不只截取文本快照。浏览器端到端自动化不是原题必选项，可用手工容器烟测补足页面链路。

## 7. 演示脚本要求

工程 Agent 提供可复制的命令或小脚本，严格按 OpenAPI 发送请求；建议使用 Cookie jar，首次 `POST /session` 保存 Cookie，后续上传、创建、查询均带同一 jar 和配置的 Origin。脚本创建的测试文件放独立目录，结束后不递归清理。

演示序列：获取会话 → 查分类与模板 → 上传所需 N 张图 → 创建成功任务 → 查询历史与结果 → 用同一批合法素材分别创建三个 failAt 任务 → 指定较长耗时连续创建三个任务 → 刷新页面/关闭页面 → 用第二 Cookie jar 验证隔离。结果必须验证 URL 能返回有效图片字节，不能只检查字段非空。

文件约定建议：`scripts/demo.ps1` 与 `scripts/demo.sh`，同一行为两种终端入口；若仅提供一种，README 给出 Windows 与容器中的等价调用。脚本不得要求真实 AI 密钥。
