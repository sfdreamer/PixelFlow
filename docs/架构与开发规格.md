# PixelFlow 架构与开发规格

版本：1.0；日期：2026-11-13；状态：待实现的开发基线。

本项目实现可独立运行的模拟素材制作网站。用户选择模板、上传图片并提交任务，Java 后台依次执行素材检查、模拟生成、结果整理；用户可以继续浏览、连续提交任务、刷新或关闭页面，随后查看个人历史和结果。本规格用于后续 Agent 实现、联调和验收，不能作为功能已经实现的证明。

## 1. 阅读顺序与约束

1. 阅读本文件，理解范围、状态机和实现边界。
2. 阅读 `openapi.json`，按字段、枚举、状态码实现接口；不得自行改名。
3. 阅读 `schema.sql`，据此创建版本化数据库迁移。
4. 按 `开发计划与验收.md` 执行开发和记录证据。

用户约束：**任何 Agent 都不得递归删除用户文件**。不得使用递归清理命令、删除数据卷或以重建目录代替修复。任务截图保留原样。初始化和测试使用独立数据库及数据目录，禁止覆盖用户素材。

当前仓库只有 `任务描述/1.png` 至 `15.png`，没有既有应用代码。以下技术选型和具体接口是本次架构决策，不是原题额外指定的要求。正文截图优先于参考 UI；接口字段由 OpenAPI 定义，数据库字段由 SQL 定义；出现冲突先修订契约及变更记录，不由各 Agent 分别解释。

## 3. 架构决策

### 3.1 技术基线

| 层 | 决策 | 理由 |
|---|---|---|
| 前端 | Next.js App Router、React、TypeScript；Node.js 22；npm 锁文件 | 符合原题；使用同源转发简化 Cookie 与文件预览 |
| 界面 | CSS Modules + CSS 变量；不强制大型组件库 | 页面数量少，易参考截图实现与维护 |
| 客户端状态 | React 本地状态 + 一个任务跟踪 Hook；Vitest、Testing Library | 分离上传、提交和任务查询状态，便于测生命周期 |
| 后端 | Java 21、Spring Boot 3.5.x、MyBatis starter 3.0.x、Maven Wrapper | 采用兼容的版本线，避免引入多套持久层 |
| 数据 | MySQL 8.4；Flyway 版本化迁移，包含 MySQL 支持模块 | 单一任务事实来源，初始化可复现 |
| 执行 | Java 单线程后台调度器 + MySQL 待处理记录 | 串行排队满足需求，不引入 Redis/MQ |
| 文件 | 后端持久卷，Java 提供受控文件流 | 刷新和后端重启后文件仍可读取 |
| 通知 | 非终态任务轮询，默认间隔 2 秒 | 易实现、易测试，无额外连接服务 |
| 环境 | Docker Compose：web、api、mysql | 便于隔离运行验收 |

版本冻结由工程 Agent 在第 0 阶段完成：选择当时可安装的 Next.js/React 稳定兼容组合，所有包、Maven 依赖和镜像固定具体版本，提交 package-lock.json 和 Maven Wrapper，不使用 `latest` 作为交付版本。上表是兼容版本线，不冒充已验证的最终依赖清单。

官方兼容依据：Spring Boot 3.5 支持 Java 17 及以上，Java 21 位于支持范围；MyBatis starter 3.0 支持 Boot 3.2—3.5、Java 17+；Next.js App Router 安装文档给出 Node.js 最低版本 20.9。工程阶段仍需安装、编译并记录具体版本。参考：[Spring Boot](https://docs.spring.io/spring-boot/3.5/system-requirements.html)、[MyBatis](https://mybatis.org/spring-boot-starter/mybatis-spring-boot-autoconfigure/)、[Next.js](https://nextjs.org/docs/app/getting-started/installation)。

### 3.2 部署与模块职责

浏览器通过同一源访问 Next.js 页面及 `/api/v1/**`。Next.js rewrite 将 API 请求转发到 Java，保留 Cookie、Set-Cookie、状态码及 multipart 内容；只做转发，不承载制作业务。Java Controller → Application Service → MyBatis Mapper → MySQL；Worker 调用阶段服务与文件存储。浏览器不能访问数据库或容器内部地址。

容器内 web 使用 `JAVA_API_ORIGIN=http://api:8080`，Java 使用 `mysql:3306`；浏览器访问 `http://localhost:3000`。禁止把 `http://api:8080` 写入返回的文件 URL。所有媒体 URL 为 `/api/v1/...` 相对路径。开发环境转发到 localhost:8080。健康探针通过 Java readiness 检查数据库和初始化状态。

| Java 模块 | 负责 | 不负责 |
|---|---|---|
| identity | 匿名会话、Cookie、当前用户上下文 | 注册、密码、会员 |
| catalog | 分类、模板及要求、公开示例封面 | 模板管理后台 |
| asset | 上传校验、文件存储、所属用户校验 | 制作执行 |
| task | 创建任务、查询、个人历史、DTO 聚合 | HTTP 请求内等待阶段结束 |
| execution | 领取队列、三阶段执行、失败落库 | 前端计时模拟 |
| storage | 安全路径、读写与文件响应 | 接受用户任意服务器路径 |
| common | 错误模型、时间、请求追踪 | 吞异常或返回伪成功 |

建议目录：`frontend/`、`backend/`、`infra/`、`docs/`、`.github/workflows/`。前端 `src/app/` 放页面；`src/features/{catalog,upload,tasks,identity}/` 放业务；`src/lib/api/` 放接口客户端和生成类型。后端按上述业务包组织，Mapper XML 位于 resources/mappers，迁移位于 resources/db/migration，示例素材位于 resources/demo。

### 3.3 身份与隔离

采用匿名持久身份，无需注册。首次进入由前端调用 `POST /session`：无有效 Cookie 时创建用户及会话；已有有效会话时返回原用户。Cookie 名 `pf_session`，随机值至少 256 bit，HttpOnly、SameSite=Strict、Path=/api，有效期 30 天；HTTPS 环境设置 Secure，本地 HTTP 演示不设置。数据库只存 token 的 SHA-256，不存明文。会话不滑动续期。

每个私有接口从会话解析 userId，禁止接受请求 body/query 中的 userId 作为授权来源。素材、任务、结果均必须按 owner 查询；访问他人的 ID 返回 404，未登录/会话过期返回 401。模板与封面公开可读。私有响应使用 `Cache-Control: no-store`；不可被 Next.js 数据缓存或 CDN 共享缓存。

浏览器 A 与隐私窗口 B 用于演示两个用户；A 刷新保持身份，B 看不到 A 的历史或素材。清除 Cookie 后创建新身份，不提供旧匿名身份找回。这是明确的演示限制，不是账号系统。当前版本没有身份切换 UI；任何重新初始化身份的路径仍必须清理旧缓存和请求。401 后停止全部查询，提示会话失效，由用户操作重新建立会话，不能静默把旧任务挂到新用户。

非安全方法验证 Origin 属于配置的前端来源；Cookie SameSite 与 Origin 校验共同防止跨站操作，拒绝不允许来源。命令行示例提供正确 Origin。后端不开放通配符凭证 CORS。日志不打印 Cookie、token 或上传图片内容。

## 4. 模板、上传和文件设计

### 4.1 种子模板

至少提供两个分类、四个模板，例如宠物肖像和旅行明信片各两个；requiredImageCount 分别包含 1 和 2。每个模板均有本地可用的封面、描述、要求、固定演示结果文件。默认仅接受 JPEG/PNG，每张最大 5 MiB（5242880 bytes）。示例图片自行制作或使用有许可的资源，记录来源、许可和复用范围；不能依赖付费或内网 URL。封面和结果使用真实可解码的图片，不能只提供失效占位地址。

模板规则持久化于 template，固定示例结果的存储键只由后端读取，不暴露为用户可控路径。后端决定素材要求，前端只渲染接口数据。模板暂不支持修改/删除，但任务仍保存标题和规则快照，保障历史语义独立。

### 4.2 上传协议与客户端状态

`POST /assets` 使用 multipart，包含 `templateId` 和单个 `file`。返回持久化 assetId 和受鉴权 previewUrl。每个上传位分别维护 `EMPTY / UPLOADING / READY / ERROR`，本地 Object URL 仅用于即时预览，服务端 assetId 才能提交任务。

选择文件后进行数量、类型及大小预检；服务端再次根据模板校验实际字节数、文件头、可解码性和 MIME 一致性。拒绝空文件、伪装图片、SVG、超过 20 百万像素的图片；图片维度在完整解码前读取，避免大图内存消耗。请求总体上限应略高于 5 MiB（例如 6 MiB），统一将过大错误转成 413，不让代理先返回无法识别的 HTML 错误。

文件保存名由 UUID 产生，忽略客户端文件名中的路径；原始文件名仅作为显示元数据。存储根目录由配置指定，规范化后的路径必须位于根目录内。先写单文件临时路径，再校验并原子移动到正式路径，随后写入数据库。数据库失败时可删除本次刚创建且经过路径确认的单个文件；禁止目录级清理。替换/移除只移除前端引用，不删除后端资产或正在执行任务引用的文件。孤立资产清理不在本次范围，README 说明演示存储会增长。

同一个上传位的选择次数生成 version。替换、移除、离页时取消请求、释放 Object URL；旧上传响应即使成功，也不能把已替换文件恢复到界面。提交条件为所有 N 个位置 READY 且 assetId 各不相同，数量必须恰好等于模板要求。

### 4.3 创建校验与结果

创建任务时复核模板有效、素材恰好 N 个、ID 无重复、归属当前用户、上传模板一致、文件存在、持久化元数据满足模板规则。assetIds 数组顺序即槽位顺序，从 0 开始落库。阶段 1 再次检查磁盘文件，以捕获上传后到执行前文件丢失等异常。

模拟生成不需处理真实图片。阶段 2 生成内部候选结果键，阶段 3 将模板预置结果复制为该任务专用结果文件，再保存 task_result 和任务成功状态。结果路径只能由后端确定。私有结果接口验证任务所属用户；成功前不提供预览 URL。结果缺失时返回 404 和 `RESULT_FILE_MISSING`，前端显示预览不可用，不把已成功任务改成失败。

## 5. 后台任务执行规格

### 5.1 状态与阶段

任务状态固定为 `QUEUED / RUNNING / SUCCEEDED / FAILED`。阶段固定为 `ASSET_CHECK / GENERATE / FINALIZE`。阶段状态固定为 `PENDING / RUNNING / SUCCEEDED / FAILED / SKIPPED`。

| 任务状态 | currentStage | result | error | 时间 |
|---|---|---|---|---|
| QUEUED | null | null | null | startedAt、finishedAt 均 null |
| RUNNING | 正在执行阶段 | null | null | startedAt 非 null，finishedAt null |
| SUCCEEDED | FINALIZE | 可预览结果 | null | finishedAt 非 null |
| FAILED | 失败阶段；启动中断可能 null | null | code/message/failedStage | finishedAt 非 null |

仅允许 `QUEUED → RUNNING → SUCCEEDED`、`RUNNING → FAILED`；服务启动收尾可将 QUEUED/RUNNING 标记 FAILED。成功或失败均为不可变终态。currentStage 在失败后保留失败位置；error.failedStage 与之相同。启动前尚未执行的中断任务允许 failedStage=null。

创建任务的同一事务写 task、三行 task_step(PENDING)、task_asset 及模拟参数快照；提交事务后返回 202 和 Location。不等待阶段执行，不在数据库事务中 sleep，不用 Controller 的请求线程执行制作。

### 5.2 最小可靠执行机制

一个 Java 实例、一个固定延迟后台调度线程，默认每 500 ms 尝试领取最早 QUEUED 任务，一次完整执行一项任务。无任务时结束本次调度；下一次由调度器触发，查询接口完全不参与。串行执行使排队容易观察并避免无界线程。

领取使用短事务：读取候选 ID 后，执行条件更新 `WHERE id=? AND status='QUEUED'`，检查影响行数为 1，再开始执行。将任务 RUNNING、第一阶段 RUNNING、startedAt、revision 在同一事务更新。调度线程不能依赖在同类中调用带事务注解的方法；使用独立事务服务或 TransactionTemplate，确保实际生效。

阶段执行顺序：

1. 先持久化当前阶段 RUNNING 并提交，之后执行该阶段逻辑及模拟等待。
2. 等待耗时结束后，若配置 failAt 命中，则记录该阶段 FAILED 和任务 FAILED，后续阶段全部 SKIPPED，立即返回。
3. 阶段正常完成，将该阶段 SUCCEEDED 和下一阶段 RUNNING、currentStage、revision 在同一短事务提交。
4. FINALIZE 成功时，结果文件已就绪；在同一事务插入 task_result、更新阶段成功及任务 SUCCEEDED、finishedAt、revision。

阶段 1 负责真实可读性复检；阶段 2 模拟生成；阶段 3 整理输出。阶段内部错误转换为有限、可理解错误码，不把 SQL、磁盘绝对路径、堆栈发给用户。成功/失败终态写入采用 status=RUNNING 条件保护，不能覆盖终态。

task DTO 由任务、阶段、结果组成，查询使用只读一致性事务，避免读到任务成功但结果为空或阶段仍处理中。每次可见状态迁移增加 revision；接口轮询不增加 revision，不写 updatedAt，不驱动阶段推进。

### 5.3 失败与模拟控制

开发/演示 profile 启用 `DEMO_CONTROLS_ENABLED=true`。创建请求可携带 simulation：failAt=null 或三个阶段之一，stageDelayMs 含三阶段耗时。默认每阶段 2000 ms；允许 0—30000 ms 整数。未传字段从后端默认配置补齐，创建时快照入 task，避免改配置影响正在运行任务。

正式 profile 中携带 simulation 返回 403 `SIMULATION_DISABLED`，不可悄悄忽略。前台常规页面不显示模拟开关；演示通过 API 请求操作即可。不随机失败、不自动重新执行失败任务。例：failAt=GENERATE 时，阶段 1 成功、阶段 2 失败、阶段 3 SKIPPED，result 必须 null。

执行错误码至少包含 `ASSET_UNAVAILABLE`、`SIMULATED_FAILURE`、`GENERATION_FAILED`、`RESULT_WRITE_FAILED`、`EXECUTION_INTERRUPTED`、`INTERNAL_EXECUTION_ERROR`。失败阶段和中文原因一并保存。任务执行失败是任务查询 200 响应中的业务状态，不能与查询 HTTP 503 混为一谈。

### 5.4 重启、数据库异常与能力边界

本版本不实现重启后自动续跑。Java 启动时，在开启 readiness 和调度前，将旧 QUEUED/RUNNING 任务标记 FAILED、错误码 EXECUTION_INTERRUPTED；已有成功阶段保留，运行阶段标 FAILED，其余 PENDING 改 SKIPPED；QUEUED 所有阶段改 SKIPPED，failedStage=null。已完成历史不改动。初始化失败不得启动调度。这是本方案的额外收尾行为，避免任务永远显示处理中。

该启动策略只支持单实例，Compose 不可扩容 API，否则新实例会错误中断其他实例任务。多实例租约和恢复执行为将来扩展，不纳入验收。

如果运行中数据库不可用：停止该任务的后续业务步骤，不在内存中宣告成功；记录 taskId、失败阶段和 traceId，暂停本轮调度。持久化失败可能使数据库保留 RUNNING，运维恢复数据库并重启 API 后由启动收尾结束这些任务。README 必须说明此限制，不声称数据库故障自动恢复。正常关闭尝试完成当前任务，超时则允许下一次启动收尾。

## 6. 数据库设计

完整 DDL 草案见 `schema.sql`。迁移基线使用 utf8mb4、InnoDB、UTC DATETIME(3)，外部 ID 使用 UUID 字符串。业务枚举由应用统一定义并由 SQL CHECK 限制，禁止级联删除。

| 表 | 关键职责 | 关系及索引 |
|---|---|---|
| app_user | 匿名用户标识 | 用户拥有多个任务、资产、会话 |
| user_session | token hash、到期时间 | token_hash 唯一；user_id 外键 |
| category | 模板分类 | sort_order 排序 |
| template | 要求、封面和预设结果键 | category_id 外键；active 筛选 |
| asset | 用户、模板、文件键及检测信息 | 用户和模板外键；storage_key 唯一 |
| task | 状态、阶段、快照、模拟参数、错误、revision | (user_id, created_at, id)；(status, created_at, id) |
| task_asset | 素材槽位顺序 | (task_id, slot_index) 主键；(task_id, asset_id) 唯一 |
| task_step | 三阶段执行边界及时间 | (task_id, stage) 主键；step_order 唯一 |
| task_result | 一项任务一个结果 | task_id 主键及外键 |

template.accepted_mime_types、task.template_snapshot、task.simulation_snapshot 是 JSON；可用 MyBatis 显式 TypeHandler 处理，禁止让前后端猜测 JSON 格式。快照规则包含 title、requiredImageCount、acceptedMimeTypes、maxFileSizeBytes 及 demoResultKey；simulation_snapshot 使用与请求相同的规范化完整结构。

多表写入事务边界：会话创建；任务受理；领取/阶段迁移；终态结果或失败。文件系统与数据库没有分布式事务：优先写成品文件，再提交成功事务；事务失败的单个输出文件可能成为孤立文件，但不能返回假成功。演示阶段不自动清理孤立文件。

列表排序固定 `created_at DESC, id DESC`。使用游标分页，不用会随插入偏移的页码；游标包含最后一条 createdAt 与 id，作为不透明 base64url 值，不承担授权作用。对用户和筛选条件重新查询，游标格式错误返回 400。任务列表默认 limit=20、最大 100，可筛 templateId；列表 DTO 与单任务 DTO 完全一致。

## 7. 接口契约与错误处理

API 基础路径 `/api/v1`；详细 Schema、required、nullable、响应码以 `openapi.json` 为准。JSON 使用 camelCase；时间返回 UTC RFC3339，例如 `2026-11-13T02:30:00.000Z`。前端按用户本地时区显示。所有任务及历史返回相同 Task DTO，不用列表与详情两套状态命名。

| 方法与路径 | 授权 | 语义 |
|---|---|---|
| POST /session | 可无 Cookie | 建立/恢复匿名身份，200；必要时 Set-Cookie |
| GET /session | 必须 | 获取当前身份，过期返回 401 |
| GET /categories | 公开 | 分类列表 |
| GET /templates?categoryId=... | 公开 | 启用模板列表，空结果 items=[] |
| GET /templates/{templateId} | 公开 | 详情；不存在/停用 404 |
| GET /templates/{templateId}/cover | 公开 | 图片文件流 |
| POST /assets | 必须 | 单文件上传，201 |
| GET /assets/{assetId}/content | 必须 | 本人素材预览流 |
| POST /tasks | 必须 | 参数校验并创建记录，202 + Location |
| GET /tasks?templateId=...&cursor=...&limit=20 | 必须 | 本人历史，包括未完成任务 |
| GET /tasks/{taskId} | 必须 | 只读任务快照 |
| GET /tasks/{taskId}/result | 必须 | 成功任务结果图片流 |

创建示例：

```json
{
  "templateId": "00000000-0000-4000-8000-000000000101",
  "assetIds": ["00000000-0000-4000-8000-000000000201"],
  "simulation": {
    "failAt": "GENERATE",
    "stageDelayMs": {"ASSET_CHECK": 2000, "GENERATE": 4000, "FINALIZE": 2000}
  }
}
```

202 响应是完整 QUEUED Task DTO（即受理时快照，即使 Worker 随后已经开始也合法），不只是 taskId；至少包含 id、templateId、templateTitle、status、currentStage、steps、result、error、createdAt、startedAt、finishedAt、updatedAt、revision。前端以 id 合并，不能替换整个历史列表。

统一错误：`{"code":"ASSET_COUNT_MISMATCH","message":"该模板需要 2 张图片","traceId":"...","details":[{"field":"assetIds","message":"需要恰好 2 项"}]}`。details 无条目时 []。字段级格式错误用 400；业务规则校验用 422；未授权 401；模拟控制禁用/来源拒绝 403；资源不存在或不属于当前用户 404；请求过大 413；不支持图片类型 415；临时依赖故障 503；未预期故障 500。不要把所有错误包装成 200。

提交校验错误码至少包括 INVALID_REQUEST、INVALID_CURSOR、TEMPLATE_NOT_FOUND、ASSET_NOT_FOUND、ASSET_COUNT_MISMATCH、ASSET_DUPLICATED、ASSET_TEMPLATE_MISMATCH、ASSET_UNAVAILABLE、FILE_TOO_LARGE、UNSUPPORTED_MEDIA_TYPE、INVALID_IMAGE、IMAGE_DIMENSIONS_EXCEEDED。文件流设置服务端检测到的 Content-Type、nosniff，私有媒体 no-store，不反射不可信文件名到响应头。

任务创建超时存在“服务器已受理但客户端未收到”的不确定窗口。本方案不自动重发 POST；提示“提交结果暂未确认，请刷新历史确认”，提供刷新历史入口，结束按钮的网络等待态，但将本次草稿置为待确认，用户明确选择新建后才再次发送。禁止宣称前端按钮防抖具有服务端幂等保证。

## 8. 前端页面与状态管理

### 8.1 页面布局

`/`：顶部品牌、当前匿名身份摘要、历史入口；分类标签；响应式模板网格。点击卡片进入 `/templates/[id]`。加载骨架、空分类、请求失败重试独立展示。

`/templates/[id]`：桌面左侧模板封面、标题、说明、N 个上传位与创建按钮；右侧当前模板的个人历史卡片。卡片展示创建时间、状态/阶段、失败原因或结果预览。小屏改为上下布局，按钮不超出屏幕。

`/history`：所有模板的个人历史，按新到旧显示及“加载更多”。详情页历史只展示该模板，离开详情后执行继续；进入历史页可查看全部。轮询管理器只跟踪当前页面已加载的非终态任务；尚未加载的旧记录在分页加载时接入跟踪。任务不因暂未在视图中显示而停止后端执行。

采用参考图的深色背景、明确面板和卡片层级，可使用单一绿色主操作色；不要求像素级复刻。上传位有可读 label，图标按钮带 aria-label，错误信息非仅颜色，焦点可见。结果预览可用 `<img>` 直接访问同源受鉴权 URL，避免服务器图片优化器不转发会话导致失败。

### 8.2 状态分层

| 状态域 | 内容 | 不允许的耦合 |
|---|---|---|
| 上传位 | file、preview、assetId、status、error、selectionVersion | 一个上传位失败不能覆盖其他位 |
| 提交 | IDLE/SUBMITTING/UNCERTAIN、submissionError | 受理后不能等任务成功才结束提交态 |
| 服务端任务 | Map<taskId, Task> | 不得用全局单一 progress/error 代表所有任务 |
| 查询网络 | 每任务 queryError、retry 状态 | 查询失败不能写 task.status=FAILED |
| 身份/页面 | userId、sessionEpoch、viewGeneration、AbortController | 旧用户/旧页面响应不能更新新上下文 |

受理成功即把任务插入本地历史并开始跟踪；提交态结束，已上传素材保留，允许用户再次明确提交创建新任务。失败后的重新提交也只能作为新建任务；没有 retry 原任务接口。

### 8.3 轮询算法

一个页面级跟踪器管理已加载任务，使用递归 setTimeout，不使用容易重叠的 setInterval。每轮对非终态、未处于查询错误暂停态的任务发 GET，并限制最多 4 个在途请求；等待本轮全部 settle 后间隔 2 秒再查询。

每次查询携带捕获的 userId/sessionEpoch/viewGeneration，完成后只有上下文仍一致且请求未取消才应用。相同任务只接受 revision 不小于本地值的快照，终态不可被旧响应覆盖。历史刷新也执行相同合并规则，不覆盖刚提交的新任务。

查询失败保留最后成功 Task DTO，单独标记“状态暂时无法更新”；暂停该任务自动跟踪并提供“恢复查询”。恢复成功且仍非终态时重新入队。401 全局停止并提示身份失效；404 对该任务停止跟踪并提示不可访问；失败业务状态来自 200 的 FAILED DTO。

某任务进入 SUCCEEDED/FAILED 立即移出跟踪集合；集合为空不再调度、不继续空轮询。离页取消请求、清理定时器，增加 viewGeneration；切换身份还清空全部用户缓存。取消请求可能无法阻止服务器处理，旧响应防护仍不可省。

刷新页面先恢复会话，再读取历史，最后将非终态任务加入跟踪。浏览器 localStorage 不保存权威任务状态；未提交草稿不要求刷新恢复。查询失败的暂停态只存在客户端，刷新重新从服务器恢复。

## 9. 工程、配置与交付约束

必须提供 `.env.example`，只含非敏感演示值；配置至少包括 DB_HOST/PORT/NAME/USER/PASSWORD、STORAGE_ROOT、JAVA_API_ORIGIN、ALLOWED_ORIGINS、COOKIE_SECURE、DEMO_CONTROLS_ENABLED、三阶段默认耗时、SERVER_PORT。私有 DB 密码不能进入 NEXT_PUBLIC 变量。Compose 数据库和文件存储均使用持久卷。

数据库迁移在 API 启动时执行；种子数据用固定 UUID 和版本化迁移，重启不会重复插入。后端演示素材打包进镜像或只读资源目录。初始化不依赖开发者电脑的绝对路径。

Compose 启动顺序 mysql healthy → api ready → web；健康检查给数据库初始化足够时间。前端构建不能依赖运行中的 Java API，页面数据在运行期加载。生产 profile 关闭模拟请求控制；演示 Compose 明确开启。后端健康信息不泄露环境变量。

日志结构包含 traceId、taskId、stage、status、durationMs、errorCode；健康检查与高频轮询日志避免刷屏。错误堆栈只在服务端日志。无需引入指标平台。

README 必须包含：准确版本、结构、构建/测试/启动命令、环境配置、连接拓扑、迁移与种子素材、身份与隔离、接口及状态、成功与三阶段失败演示、耗时调整、多任务与刷新恢复、重启策略、已完成与未完成、已知限制、实际投入与取舍、部署/回滚、AI 工作流示例、开源与素材来源。不得虚填投入时长或测试通过情况。

部署：校验配置和卷位置 → 备份数据库及素材 → 构建版本化镜像 → 启动 Compose → readiness 和烟测。回滚优先恢复上个应用镜像；不兼容迁移必须按已验证备份恢复方案处理，不直接运行破坏性降级 SQL。停止服务不删除卷，任何清理均须遵守用户禁止递归删除约束。

## 10. 变更规则与后续扩展

本基线允许工程 Agent 冻结补丁版本、具体组件样式与测试库补丁，不允许未经记录改变任务枚举、错误模型、接口字段、身份隔离、阶段顺序或终态语义。必要变更先更新契约和设计、描述影响，再同步所有调用方和测试。
